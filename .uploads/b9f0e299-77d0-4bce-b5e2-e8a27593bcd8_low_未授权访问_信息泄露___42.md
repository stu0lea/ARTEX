## 概述

`icsc.mall.icbc.com.cn` 是工行"慧餐通教育缴费平台"的移动端 H5 前端，其后端 BFF 网关前缀为 `/user/getapi`（由前端主包 `/user/static/js/index.b82a1eed.js` 中 `u="/user/getapi"` 硬编码确认）。该网关对约 220 个后端接口按路径做鉴权，但**白名单粒度失控**：一批"登录前"配置类接口在完全无 Cookie、无 Token、无任何自定义认证头的情况下直接返回业务数据，包括

- **全量多租户目录**（河南 16 个地市、26 个 `tenantId` 及其开通场景），以及平台域名/标题等场景配置；
- **微信公众号 OAuth 参数**（`appid=wx130695d4d121f98c`、回调 `redirect_uri`、`scope=snsapi_base`、`state`）；
- **内部 API 域名** `https://imapi.icbc.com.cn`（由 `sysParam/queryAccessTokenUrl` 直接下发）；
- 灰度开关状态（`enableNewHome`）、会话清理接口（`cleanCookie`，GET 语义改状态）；
- 统一的 OAuth2 登录跳转地址与客户端标识（`clientId=auth2IcscPageUser-Client`、`appId=0103`、注册渠道/类型、默认 `deviceId` 等）。

这些信息本身不能直接登录或取数，全部业务数据接口（订单、学生、地址、账户余额等）在未认证下均返回 401；但泄露面为攻击者提供了**多租户路由键（tenantId）与登录链路完整参数**，可直接用于后续定向枚举、越权与 OAuth 链路攻击，属于典型的"安全配置/认证缺失类信息泄露"。

## 影响与危害

**已确认可获取：**

| 泄露项 | 具体内容 | 危害 |
|---|---|---|
| 多租户目录 | 26 组 `cityName + tenantId`（如 周口=0102、郑州=0103、平顶山=0312 …），含 `provinceName` 与每租户开通的 `scenes`（缴费/食堂） | `tenantId`/`appId` 是该平台所有业务请求的路由键，泄露后攻击者可按租户精准构造后续请求、定向枚举各校/各校区的缴费与食堂业务，降低攻击成本 |
| 场景配置 | `domainName=https://icsc.mall.icbc.com.cn`、`title=教育缴费`、`backGroundImgKey` | 辅助识别系统边界，风险较低 |
| 微信 OAuth 参数 | `appid=wx130695d4d121f98c`、`redirect_uri=https://icsc.mall.icbc.com.cn/user/pages/loginChoice/index`、`response_type=code`、`scope=snsapi_base` | appid 在 OAuth 流程中本身对客户端可见，单独泄露价值有限；但结合固定回调地址，可为进一步的授权码链路分析（授权码窃取/回调白名单校验）提供起点 |
| 内部地址 | `https://imapi.icbc.com.cn` | 泄露内部 API 域名，可用于内网/内部服务面测绘 |
| 登录链路参数 | `clientId=auth2IcscPageUser-Client`、`appId=0103`、`userRegisterChannel=01`、`userRegisterType=01`、`cateringCanteenFlag=1`、`withCreateFlag=1`、`verifyChannel=0`、`deviceId=icscDeviceId001`、`welcomeTitle/welcomeMessage` | 完整还原统一认证（`loginecp.mall.icbc.com.cn`）登录入口构造方式，便于对 OAuth2 登录接口做参数污染/PKCE 降级等专项测试 |
| 灰度/会话接口 | `oAuthClient/enableNewHome` 返回开关；`app/cleanCookie`、`app/cleanCookieWithDealGray` 返回 `code=0` | `enableNewHome` 无害；`cleanCookie` 是 GET 语义的会话操作，存在跨站强制登出（CSRF-logout）风险（**未对已登录会话验证，需进一步确认**） |

**判定为低危的理由（不做夸大）：**

1. 泄露内容不含任何 PII、账号、口令、Token、密钥或业务数据；未认证下 213 次探测中 180 次返回 401（`{"LoginUrl":...}`），订单/学生/地址/余额等敏感接口均被正确拦截；
2. 微信 `appid` 与回调域名在 OAuth 流程中本就对浏览器/客户端公开，实质增量信息有限；
3. 租户目录在登录页面上通常需要展示（按地市选择），可能属于设计预期，属"白名单过度/信息最小化不足"而非可直接利用的数据泄露；
4. 已实测写操作接口被 CSRF Token 网关拦截（`{"code":"20001014","msg":"CSRF当前接口禁止访问"}`），无法在未认证状态下造成数据写入。

**最坏后果（需前置条件）**：若后续任一租户的微信 `snsapi_base` 链路可获取 `openid` 会话，攻击者可凭借本处泄露的 `tenantId` 列表 + `appId` 逐个租户试探 `getOrderDetails`、`listStudentOrders`、`getAddressList`、`accountBalance` 等接口的越权（IDOR），此时才能升级为读取学生/家长敏感数据的中高危问题。当前阶段不具备该条件。

## PoC

```bash

UA='Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 Mobile/15E148'

$CURL -o /dev/null -w '  userInfo -> %{http_code}\n' "$BASE/api/user/client/userInfo"
```

## 根因分析

1. **BFF 网关采用"按路径白名单放行"而非"默认拒绝 + 显式放行最小集"**：`/user/getapi` 下 220 个接口由统一拦截器鉴权，但白名单是按 controller 分组整体放开的（`/sysParam/*`、`/oAuthClient/*`、`/app/*`、`/tenantArea/*`、`/client/*` 中的部分方法），导致同组内的"配置类/工具类"接口被一并暴露。
2. **前后端职责划分不当**：`sysParam/queryAccessTokenUrl` 本质是"服务端配置读取"，应当只在服务端内部使用，却作为公开接口把内部域名 `imapi.icbc.com.cn` 直接下发给浏览器；`oAuthClient/enableNewHome` 等灰度开关同理。
3. **信息最小化缺失**：`tenantArea/initAreaPage` 一次性返回**全部 26 个租户**（含未在当前 appId 下使用的租户），而登录页实际只需当前租户或按省/市聚合的最小集合；`tenantId` 又是全局业务路由键，等价于把多租户拓扑公开。
4. **参数校验先于鉴权**：`dealAppGrayTag?appId=`、`mall/member/scene/check/bannerShare/previewBannerInfo` 在未认证状态下返回"参数不能为空 / appId不能为空"（`00000002`），说明校验逻辑在过滤器之前执行，攻击者可借此判断接口存在与参数结构，属典型的鉴权顺序缺陷，为后续参数探测留下空间。
5. **GET 语义改状态**：`app/cleanCookie`、`app/cleanCookieWithDealGray` 用 GET 执行会话清理并返回 `code=0`，缺少 CSRF Token 校验与幂等语义，具备跨站强制登出条件（未对已登录会话实测）。

## 修复建议

**立即（低成本、可直接上线）**

1. **收敛白名单为显式最小集**：把 `/user/getapi` 的免鉴权清单改为逐条枚举（仅保留登录页真正需要的极少数接口，如地区/首页配置），删除 `sysParam/*`、`oAuthClient/*`、`app/*` 的整组放行；对未列入清单的路径一律在网关层拒绝（返回 401），不要下沉到 controller。
2. **`sysParam/queryAccessTokenUrl` 与 `oAuthClient/enableNewHome` 移出公开面**：内部域名与开关改为前端构建期静态配置（或由登录后接口下发）；如必须运行时下发，则要求最小会话（匿名 session + 签名）且只返回与当前 `appId` 绑定的值。
3. **`tenantArea/initAreaPage` 做信息裁剪**：只返回当前 `appId`/host 对应租户或省市级聚合（不含 `tenantId` 原值）；如页面确需全量地市列表，改为后端维护的静态 JSON（CDN 发布），并去掉 `tenantId` 字段，改由服务端按 host/appId 映射。
4. **`app/cleanCookie*` 改为 POST + CSRF Token**，并限定只清理当前会话；同步检查是否有其它"GET 改状态"接口。
5. **修正鉴权顺序**：把参数校验前移到鉴权之后，未认证请求统一返回 401，不再泄漏"参数结构/接口存在性"差异。

**短期加固**

6. 对 `tenantArea`、`redirectWxCode` 等公开接口加**频控与异常枚举检测**（单 IP/单 session 阈值、连续遍历不同 `appId` 告警），并接入 WAF 规则。
7. 对 `redirectWxCode` 的 `appId` 做合法性校验与白名单（仅允许平台已注册的 appId），避免被用作任意 appId 的探测/回显点；确认微信后台的 `redirect_uri` 授权域名白名单已收敛（当前回调固定为 `https://icsc.mall.icbc.com.cn/user/pages/loginChoice/index`）。
8. 复核 `loginecp.mall.icbc.com.cn/oauth2/login/auth` 对 `clientId/appId/urlParams/icscParams` 的处理：对参数做白名单与签名，禁止客户端控制 `deviceId`、`welcomeTitle/welcomeMessage` 等展示字段被外部拼装；对 `codeChallenge` 强制校验（防 PKCE 降级）。

**长期**

9. 建立"**默认拒绝**"的网关基线：新增接口默认需要认证，免鉴权必须走审批并在配置中显式登记，配合 CI 检查。
10. 把"未认证可达接口清单 + 返回字段"纳入常态化巡检（每次发布比对差异，一旦新增未鉴权接口即告警），并将本次泄露的 `tenantId` 列表作为资产敏感字段纳入数据分级管理。
11. 前端打包产物避免硬编码内部域名/测试地址（本次主 JS 中还发现 `realServerDomain 122.23.173.105:8080`、`mockServerDomain unicorn.sdc.cs.icbc`、`testCookie ICSCUSERSESSION=63b8fa07-...` 等测试环境信息，虽实测该 session 在当前生产无效，仍属应清理的构建残留）。
